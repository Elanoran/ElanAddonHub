# Elan's Outpost changelog

Newest first. `Tools/release.py` (addon repo) reads the sections newer than the previous release for the GitHub release notes.
Keep one `## x.y.z` section per hub version. This file is also shown in the Outpost (Settings > About > What's new): public text only - no paths, names, addresses or keys.

## 3.1.1
- Fixed: the 3D world map's buildings now show their real texture colours - the game lists many textures twice and the Outpost picked the copy that isn't on your disk.
- Fixed: the world map's "Copy details" now says why an area couldn't be read - not in the game's file list, listed but not on your disk yet, or on disk but unreadable - for the map pictures, the heights, the buildings and their textures. 3D buildings made by an older Outpost are remade where they can now get their real colours, and a texture that couldn't be read is tried again next time.
- **Knows Lodge server 2.31.1.** Internal: the signed Cairn messages and the public-address check now come from one shared definition with the Cairn and the Outpost; the address check now refuses the same special addresses the Cairn refuses; every Lodge message type now comes from one shared list, checked by tests; every Lodge message is now typed on both sides, from one shared definition. Two small Lodge server fixes: the Guild Master's switches for badges and for the Cairn always reach the right part of the server, and a Lodge that doesn't take part in the Cairn now answers the Outpost's Cairn questions with a clear "not offered here" instead of staying silent.
- **Lodge server 2.31.1 safety:** a message holding an extreme number of items is refused before it is read; wrong-code lockouts and rate limits count an IPv6 /64 as one address, so someone rotating addresses can't lock everyone else out, and members with a saved device still get in; chat and shared files have a download budget per person and hour; more dangerous file types are refused (the same list the Outpost warns about) and zips uploaded in chat are checked for programs inside; status notes are cleaned of hidden and direction-changing characters, and error messages no longer show server internals.
- Internal: the checks of update, Cairn data and Cairn notice signatures now use the same code as the Lodge and the Cairn, with its own tests; nothing changes in what you see.
- Internal: the connection to a Lodge now reads and writes its messages with .NET's own JSON engine, the same as the Lodge server, with limits on size and depth.
- Safety: updates must carry a valid signature; downloads from a Lodge are capped in size and time; voice only plays members of your room; invite links can't hide another address; a saved login is never sent to a different Lodge; names and pinned text are cleaned like messages; more dangerous file types are warned about; an older Cairn dataset is never accepted.

## 3.1.0
- **The Outpost now runs on .NET 10** (it ran on .NET Framework 4.8 until now). Loading the game data is about a quarter faster on the first start, and the Outpost now uses the same up-to-date foundation as the Lodge and Cairn servers, with current security fixes. It looks and works the same.
- **One-time setup:** .NET 10 needs Microsoft's free ".NET Desktop Runtime 10" on your PC. If it is missing, Windows shows a message with a download link when the Outpost starts - install it once and start the Outpost again.
- The radio now uses the modern way of streaming: switching channel or quality closes the old stream before the new one starts.

## 3.0.1
- **Back in your voice room after an update.** When the Outpost restarts for an update while you are in a voice room, the new version goes straight back into the same room, muted or deafened as you were. It only does this right after the update (within 10 minutes) and only on the same Lodge, so a normal start later never joins voice by itself.
- **Elan's Priest Helper.** The new priest add-on is listed with the others: heal frames with click-casting, your Renew and shield timers, a buff manager, the five-second rule and a healer coach. Addon health knows it too (/epr diag).

## 3.0.0
- **Notices from the Cairn.** When something important comes up - a security fix for Lodge servers, maintenance, news - the Cairn's operator can now send a short notice to the Lodges, and it shows at the top of the Lodge page. The Guild Master and officers see every notice, other members only the important ones, guests none. Each notice is signed with the Cairn's key and the Outpost checks that signature, so a notice that says "From the Cairn" really is from the Cairn - a Lodge can pass one on but can't write or change one. Close it with the cross; when an officer has seen it, the Cairn is told that the message arrived.
- **Knows Lodge server 2.31.0.** A Lodge's Guild Master and officers see the update notice for it: the server passes the Cairn's notices on and keeps a log of suspicious requests (wrong invite codes, floods, oversized requests) so its operator can spot trouble early.

## 2.99.0
- **Signed updates.** Every release is now signed, and the Outpost checks that signature with keys built into it before it trusts anything in the update information - the update itself and every add-on. An update that is signed wrongly is refused and nothing is installed from it, so a release someone uploaded with a stolen GitHub login alone can't reach you. Older releases had no signature; for now an unsigned one is still accepted (and noted in the log), a later release will refuse those too.

## 2.98.2

## 2.98.0
- **Your Lodge on the world map, just like you.** Members who share their map position with you are now drawn the same way as your own position, on the flat map and in 3D: a dot in their class colour with a heading arrow, a trail of the last 10 minutes that fades out behind them, and the paw prints when you zoom in - hoofprints when they ride, ripples when they swim, and a hunter's pet trotting beside them while it is out. In 3D they stand at the right height on a building's floor, on the water or on a flight, like you do. Their trails are kept in memory only and go the moment they stop sharing, leave or go invisible.

Click a name to follow them - if they are on another map (another continent, an island), that map opens first - and click it again to stop. The card always says what is followed ("Following you", "Following Wing"); following one stops the other, and dragging the map stops it as before. The dot's own **Follow this member** stays.

## 2.95.0

With the game's advanced combat logging (the Toolkit turns it on with the log) it also shows the creature's health at the levels you met it at, and where you fought it, as "Fought" in "Seen at" and on the maps.

The log files themselves are only read, never changed or deleted, and the Outpost reads on from where it stopped, a little at a time. This stays on your PC for now; sharing it with your Lodge comes later.

## 2.88.0
- **Learned flight paths.** WoW Forever flies some flight paths differently from the game files, so the world map's flight routes (and the 3D dot on a flight) could follow the wrong line. While your live position is on, the Outpost now notes the line each flight really takes, from the flight master you took off at to the one you land at (a flight with stops is cut at the masters it passes).
- **Two flights that agree win.** When two of your flights of the same leg agree with each other and both clearly differ from the game files, that line becomes a learned route. One odd flight (a /reload in the air, missing samples, a teleport) is never enough. If a later flight follows the game files again, the learned route is dropped - Forever may change it back.
- **On the map.** The Flight routes layer draws a learned route as a solid teal line instead of the game's dashed one, with the tooltip "Learned from your flights: differs from the game files". The 3D dot follows it on a flight, and the leg's flight time comes from your recorded flights when nobody else measured it.
- **Shared with your Lodge.** With "Share flight times with the lodge" on, your learned routes are shared too (only the simplified line between two flight masters, its flight time and how many flights agree). Routes your Lodge's members agree on show up for everyone as "Learned by your Lodge". Your own newest flight always counts first.
- **Kept small.** Only the simplified line, its flight time and the game version are kept on your PC - no times of day, no names. Settings > General > Learned flight routes shows what was learned and has a **Clear learned routes** button.
- **Paw prints on your live trail.** Zoom in on the world map (2D or 3D) and your trail of the last 10 minutes turns into little footprints in your class colour, left and right along the way you went, fading with age like the trail. Zoomed out it stays the clean line it was.
- **Prints for how you travel.** On foot you leave paws (hooves for tauren, bony prints for the undead, tiny prints for gnomes), on a mount bigger hoofprints further apart, on a flight a light dotted line with now and then a feather, swimming little ripple rings, and as a ghost faint wisps. Hunters get a second, smaller line of their pet's paws trotting beside them.
- **Lying on the ground in 3D.** In the 3D view the prints lie on the ground and follow its slopes, on the floor of a building or on the water when that is where you were, and the flight's dots float in the air along the route.
- **Your choice.** "Paw prints" is a new row in the map's layer list (on by default; it only shows while your live position is on). New prints fade in gently, unless animations are switched off in Windows.
- **Elan's Hub 1.17.0** tells the Outpost whether you are mounted and whether your pet is out (part of the same off-by-default "Share my map position" option). With an older Hub the trail shows paws while riding, and a hunter's pet line is always drawn.

## 2.87.0
- **Orgrimmar and Stormwind in the 3D world map.** With "All buildings" switched on, Orgrimmar now shows its city in the canyon - The Drag, the Valleys, the huts and the gates - instead of bare rock, and Stormwind gets its streets, canals and districts, not only its walls and castle. These two cities are built as one large model whose open-air streets the game marks as "inside" the city; the 3D map used to leave all of those out. Rooms and halls you only see from inside (and Ironforge and the Undercity, which are under ground) still stay out. Thunder Bluff, Darnassus and the towns are unchanged.
- **Your buildings update themselves once.** If you already made the buildings, the next time the 3D map opens with buildings on it remakes just the few models that changed (a few seconds in the background, no question asked); everything else is kept.
- **Better heights for your live dot in these cities.** The live position's building floors use the same models, so walking through Orgrimmar's streets now follows the city's own ground.
- **The Cairn's data is for those who share.** The Cairn's numbers from other lodges now come only from your own Lodge, and only while "Share my Atlas observations with this Lodge" is on (Settings > Lodge). Like a fair deal: lodges that contribute receive, and members who share get it from their lodge. The Outpost no longer downloads anything from the internet for the Cairn.
- **Sharing off means no Cairn data.** Turn sharing off and the Cairn's copy on your PC is deleted at once; your lodge is told, and nothing more comes until you switch it on again. Guests and players without a lodge don't get the Cairn's data. If your lodge itself stops contributing, it stops handing the data out, and your copy is deleted too.
- **Settings > Privacy explains it.** The "Cairn open Atlas data" switch is gone. In its place a short note says how it works, with a button to the sharing switch and a line saying where your Cairn data came from (or why there is none). Rows labelled "Cairn" in the Atlas stay as they were.
- **A friendly guide to sharing.** The welcome guide has a new Sharing step: what is shared (what you see in the world - drops, vendors, where creatures and nodes are, quests and rare finds; ids and counts, no character names), with whom (your Lodge, and through it the Cairn) and why (everyone's Atlas gets better, and the Cairn's numbers come back to those who share). The switch is right there, and "Not now" counts as much as "Share".
- **One calm question for members who don't share.** If you are in a Lodge with sharing off, Atlas Home asks once - Turn on, Not now, or What is shared? - and remembers your answer. It only asks again if your Lodge starts offering something new, like the Cairn's numbers. Where the Cairn's rows would show on an item or creature page, a single quiet line says they are for members who share, with a link to the switch.
- **For lodge owners:** a lodge that contributes to the Cairn now also receives the Cairn's data and hands it to its members who share. If the lodge has not contributed for a while, the Cairn stops sending it until the next contribution, and the server log says why.

## 2.86.0
- **The Cairn: open Atlas numbers from many lodges.** The Atlas can now also show the Cairn, an open dataset that merges what many lodges observed: drop rates of creatures, objects, fishing and gathering, vendor items and prices, spawn points, gathering nodes and flight times. It holds ids and counts only - no names of people or characters - and is free for everyone (CC0). A number only gets in when at least two independent lodges saw it, and numbers far off from the rest are left out.
- **Labelled "Cairn", below your own lodge.** On item and creature pages the Cairn's rows carry the label "Cairn" and sort below your lodge's own observations. Where your lodge already shows a source, the Cairn's figure rides along as a second line.
- **Your choice in Settings > Privacy.** "Cairn open Atlas data" is on by default because it contains no personal data: the Outpost downloads the file about twice a day and checks it before using it. It only downloads - nothing is ever uploaded to the Cairn. Switch it off and nothing is fetched and the downloaded copy is deleted. If your lodge's owner contributes the lodge's pooled Atlas numbers to the Cairn, the Privacy page tells you so.
- **For lodge owners: "Contribute to the Cairn"** is a new opt-in server setting, off by default. When switched on with the Cairn's address and a key from the Cairn's admin, the server sends the lodge's pooled Atlas totals about once an hour - ids and counts only, and only what members already share with the lodge's Atlas.

## 2.84.0
- **Dungeon maps say why they are drawn again.** When a game update (or a new Outpost version that draws more) means a dungeon map has to be drawn again, the card says so ("Your game was updated, so the Outpost draws this map again ...") instead of "The first time only".
- **Dungeon and raid maps in the game's own look.** For dungeons and raids that have no map picture in the game, the Atlas draws a plan of each floor. Now it lays the game's own minimap pictures of the rooms over that plan - the same pictures the in-game minimap shows inside the instance - so Molten Core, Blackrock Depths, the Deadmines and most others look like they do in the game. Where the game has no picture for a part (the Deadmines' surface buildings, for example), the plan shows there as before.

- **Creatures on the dungeon maps.** If you have the Classic data (the Classic baseline: the Atlas page's **Get Classic data**, or from your Lodge), the drawn dungeon and raid maps now show who stands where: the bosses as red markers numbered in the route's order, the other creatures grouped into pulls (the number in the dot says how many), rares in gold and patrols with a dashed line of their walk. Point at a marker for the names and levels; click it for the creature's page. The positions are where the creatures stand in Classic, so this server can differ here and there.
- **Warnings in plain words.** A small "!" marks creatures that change how a pull goes: they fear, mind control, silence, heal, summon help, are stealthed, or run or call for help. The hover text names the spell (for example "Fears: Terrify" or "Runs for help at low health"). Only what the game data says is shown.

Where it crosses a ramp, bridge or water the map has no floor for, it is dashed; where it changes floor, a small tag says to which floor. It is a suggestion worked out from the map, not a guide: doors, levers and events are not in it.
- **Pick what you see.** The chips at the top left of the map (Bosses, Pulls, Rares, Route) turn each part on or off, for every dungeon while the Outpost is open.
- The creature data is read once from the Classic baseline files already on your PC (a few seconds) and kept until the baseline changes. Maps drawn before this version are drawn again once, to add where you can walk.
