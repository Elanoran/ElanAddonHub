# Elan's Outpost - design rules

Goal: calm, consistent, a little Apple-like. Restraint over decoration: few colours, few sizes, quiet motion.
Tokens live in `src/Theme/Theme.xaml` (names below), motion helpers in `src/Motion.cs`. Old short keys
(`Bg`, `Surface`, `SurfaceHi`, `Text`, `TextDim`, `Accent`, `Gold`, `Danger`, `Line`, `Icons`...) still work as aliases; new UI uses the token names.

## 1. Spacing (4-pt scale)
`Space.XS 4` `S 8` `M 12` `L 16` `XL 24` `XXL 32` `XXXL 48`. No other margin/padding values.

| Use | Token |
|---|---|
| Card inner padding | 16 (`Pad.Card`); dense list row 16,12 (`Pad.Row`) |
| Gap between cards | 12 (`Gap.Card`) |
| Gap between sections | 24 (`Gap.Section`) |
| Page margin | 24 (`Pad.Page` = 24,8,24,24); settings pages 32 |
| Icon to label | 4-8; button to button 8; title to subtitle 2-4 |
| Content column | pages use the full width of the window; the Addons page in List view stops at 960 (`AddonsListMaxWidth`), left-aligned |

## 2. Radii
Window 14 (`Radius.Window`), card 12 (`Radius.Card`), large control / art thumbnail 10 (`Radius.ControlLg`), control 8 (`Radius.Control`),
chip / pill = half its 24 px height (`Radius.Chip` 12), avatar = circle (`Ellipse`). Nested shapes: inner radius = outer radius - padding.

## 3. Typography
Segoe UI (Segoe UI Variable is not used: WPF on .NET Framework maps its weights badly). Mono (`Font.Mono`) for code, paths, ids only.

| Style | Size / line | Weight | Colour | Use |
|---|---|---|---|---|
| `Text.Title` | 22 / 28 | Semibold | Primary | page title (one per page) |
| `Text.Section` | 15 / 20 | Semibold | Primary | card title, section header |
| `Text.RowTitle` | 13 / 18 | Semibold | Primary | title of a compact list row |
| `Text.Body` | 13 / 18 | Regular | Primary | main content, version line |
| `Text.Secondary` | 12 / 16 | Regular | Secondary | subtitles, descriptions, notes |
| `Text.Caption` | 11 / 14 | Regular | Secondary | stats, timestamps, labels |
| `Text.Mono` | 12 / 16 | Regular | Primary | code |

Rules: at most ONE semibold element per row. Hierarchy comes from size and colour role, not from bold or ALL CAPS. Never text below 11.
Glyph (icon-font) sizes are separate from the text ramp: 12 inline with text / status, 16 in rows and buttons, 20 in the rail and big tiles, 32 for a hero glyph. Nothing else (no 9, 10, 14, 18).

## 4. Colour roles
- Layers (darker = further back): `Brush.Bg` #0F1113 < `Brush.Surface1` #16191C (cards) < `Brush.Surface2` #1E2226 (inputs, hover rows) < `Brush.Surface3` #262B30 (popovers, tooltips).
- Text: `Brush.Text.Primary` #E8EAED (14.6:1 on Surface1), `Secondary` #8A9199 (5.5:1, AA for body), `Tertiary` #6F767E (3.8:1: icons, hints, never essential text), `Disabled` #4B5258.
- Accent `Brush.Accent` #ABD473 (+ `.Hover`, `.Pressed`, `.Tint`, `Brush.OnAccent` for text on it): ONLY for the primary action and for selection. Not for plain text, numbers, dividers or decoration.
- Status, only for status: `Brush.Success` / `Warn` / `Danger` / `Info`, each with a `.Tint` (15 %) fill for chips.
- WoW class colours: only to identify a class/character.
- Window: `Brush.Window` (2.70), a calm solid gradient (`Color.Window.Top` #121519 to `Color.Window.Bottom` #08090B), darker than the page panel. No picture behind the pages: nothing ever shows through a page, a menu or the navigation.
- Page panel: `Brush.Panel` (solid Bg, radius Card). Pages sit on a page panel (Settings nav + content, Inventory, Browser, Lodge, Atlas, Talents, Professions); their side navigation has no card of its own, the panel is its background; cards on the panel are Surface1, inputs/segments Surface2, so no text shadows are needed. `Brush.Scrim` (Bg at 75 %) is only the dim behind an overlay inside a page (a sheet, a form, the welcome guide).
- Overlays (white veils, work on any surface): `Brush.Overlay.Hover` 6 %, `Pressed` 10 %, `Chip` 8 %, `Brush.Divider` 7 % hairline, selected = `Brush.Accent.Tint` 16 %.
- Media and game surfaces (viewers, in-game overlay; never on regular pages): `Brush.Scrim.Strong` (85 % black backdrop of the picture / video viewers), `Brush.Scrim.Glass` (40 % black behind round glyph buttons over a picture, also `Color.Scrim.Glass` for gradients), `Brush.Scrim.Disc` (the play disc over a thumbnail), `Brush.Media` (video letterbox), `Brush.Game.Pill` / `.Active` (the in-game voice overlay pills), `Brush.Rail` (the navigation rail: solid since 2.70). `Brush.Dungeon` (violet) is the one extra status colour: "In a dungeon". `Brush.Press.Dark` / `.Soft` darken a filled control while pressed, `Brush.OnDanger` is text on a danger fill.
- Identity colours are data, not theme: WoW class colours, item quality colours, rank frames (Guild Master orange ... Initiate grey), the avatar palette and accent swatches. They stay as hex in code (`ClassColors`, `QualityHex`, `RoleColor`, `AccentHex`), nowhere else.
- Painted art (`src/Assets/Art`, JPEG, mapped in `ArtLibrary.cs` by zone id / category id / class + tree): only in its slots (zone banner 176 high at the top of a zone page, the same banner at the top of a category browse page since 2.71, talent tree panels; no window background since 2.70, no art on the Atlas Home tiles since 2.71), always UniformToFill around a focal point and always under a veil token so text stays readable: `Brush.Art.Veil` (Bg 62 %, talent trees), `Brush.Art.HeroFade` + `Brush.Art.HeroCard` (zone and category banners: clear at the top, the page colour at the bottom, the header card see-through), `Brush.Art.BannerFade` (clear to the page panel colour at the bottom). A slot without art keeps its plain look.
- Category icons (`src/AtlasIcons.cs`, 2.71): own line art, one per Atlas category, on a 24 x 24 grid with a 1.6 stroke, round caps and joins, no fill; the stroke takes a text brush (Secondary in rows and tiles, Primary when selected or in a banner header). Sizes 12 / 16 / 20 / 24 / 32 by the slot (Recent rows, palette rows, nav rows, Home tiles, banner header). Used on the Home tiles, the Atlas side navigation and the Ctrl+K page results; anything else keeps the icon font.
- Section colours (2.71.1; `Brush.Section.*` in `Theme.xaml`, checked by the `menucolors` self-test): the secondary menus beside a page - the Atlas side navigation, the Lodge sidebar, the Characters list and the Settings menu - sit on `Brush.Section.Panel` (#14171A: the page panel lifted a few % towards slate, still darker than a Surface1 card) and give each section a soft hue of its own. Eight muted hues of about the same lightness (`Color.Section.Teal` #6CBFB5, `Green` #8DBE92, `Amber` #D9AE62, `Violet` #B19CE0, `Blue` #7FA9DB, `Rose` #D990AA, `Orange` #DC9A6E, `Slate` #9DA8BA) and `Neutral` #8A9199 (= Text.Secondary); none is the accent green or a status colour. Each section is a pair of tokens, `Brush.Section.<Name>` (the hue) and `Brush.Section.<Name>.Tint` (the same hue at 16 %, like `Brush.Accent.Tint`):

  | Menu | Section -> hue |
  |---|---|
  | Atlas side navigation | `Database` teal, `World` green, `Character` amber, `Lodge` violet; Home, Pinned, Recent, Data sources and an unknown group `Neutral` |
  | Lodge sidebar | `Calendar` orange, `Files` teal, `Ladder` amber, `Channels` (Text channels) blue, `Voice` (Voice rooms) rose, `People` (the online groups) violet |
  | Settings menu | `General` slate, `Addons` teal, Lodge = `Lodge` violet, `Profile` amber, `Privacy` blue, `Voice` rose, `Overlay` green, `GuildMaster` orange, `About` neutral |
  | Characters list | the character's own class colour (identity data, `SelectTintOf`: the class colour at 16 %); "All characters" `Neutral` |

  Where the hue goes, and nowhere else: the group label (`Text.Caption` in the hue instead of Tertiary), the rows' 16 px icons (at rest too), and the selected row: its fill is the section's `.Tint` and a 4 x 16 bar (radius 2) in the hue sits at its left edge (`Side.Row`'s `BorderBrush`, the `ind` part of the Settings `Nav` and Characters `SideRow` templates). Row names keep their text colours (Secondary, Primary + semibold when selected), so the text is never coloured: every hue reads at least as well as Text.Secondary on the menu fill (5.6:1) and Text.Primary on any section tint stays >= 7:1 (11:1). The main left rail is not coloured. Selection elsewhere (palette hits, segments, chips) stays `Brush.Accent.Tint`.
- `Line`/outline borders: avoid. Separate with fill, elevation or a `Brush.Divider` hairline.

## 5. Elevation
0 flat: fill only. 1 raised card (`Card.Raised`): Surface1 fill + 1 px top highlight (`Brush.Edge`) + soft shadow (blur 16, y 2, 30 %). 2 overlay (dialogs, menus; `Elevation.2`): Surface3 fill + hairline + big shadow (blur 40, y 12, 50 %). No outlines to express hierarchy.

## 6. Motion
Fast 120 ms (hover tints, pressed), Standard 180 ms (expand/collapse enter, page, chevron), Emphasized 240 ms (large moves). Enter = cubic ease-out, exit = cubic ease-in (exit may use Fast). No bounce, no overshoot, nothing loops except spinners.
- Hover: white veil fades in (`Motion.HoverIn/Out`); cards also lift 1 px and deepen the shadow.
- Expand / collapse: `local:Motion.Expand="{Binding Expanded}"` on a Border (height + fade); chevron: `local:Motion.Turn`.
- Page switch: `Motion.PageIn(page)` = fade + 8 px slide up (Settings sub-pages too). Dialog: `Motion.DialogIn/DialogOut`, scale 0.96 to 1 + fade. Long scroll lists: `local:Motion.EdgeFade="True"`.
- Reduced motion: `Motion.Enabled` / the `Motion.*` durations collapse to 0 when Windows animations are off (`SystemParameters.ClientAreaAnimation`). Never animate without going through these.

## 7. Icons
Segoe Fluent Icons (falls back to Segoe MDL2 Assets: `Font.Icons` / `Icons`), 16 px in rows and buttons, 20 px in the rail. Colour by role: Tertiary at rest, Secondary/Primary on hover, Accent only when selected. Addon and avatar art is our own flat vector style (see AddonIcons/Avatars.xaml); do not mix in photos or outlines.

## 8. Components
- Buttons (radius 10, never outlined): Primary (accent fill, one per view), Secondary (8 % white veil), Ghost (text only), Danger (confirm of destructive dialogs). Heights 28 (`Button.S`), 32 (`Button.M`), 36 (`Button.L`). Hover veil 120 ms, pressed darkens, disabled = Tertiary text.
- Focus ring: 2 px `Brush.Focus` (accent), rounded, 2 px outside the control, keyboard focus only.
- Pill / status chip (`StatusPill`, `Chip`): 24 high, full-round, tinted fill, regular 12 px text, status colour only for status. A pill that acts (Update, Install) is accent-filled.
- Card (`Card.Raised`): inner 16, radius 12, title Section, subtitle Secondary, stats Caption. Header toggles details.
- List row: 16,12 padding, 36 px leading tile, `Text.RowTitle` + `Text.Secondary`, chevron right (Tertiary).
- Settings row (`Setting.Row`, a `HeaderedContentControl`): `Header` = label (Body), `Tag` = helper (Secondary, optional), content = the control, right-aligned and centred; 12 px above/below, hairline `Brush.Divider` between rows only. Rows live in a `Card.Rows` card (16 side padding, first hairline clipped); form bodies use `Card.Group` + a 16 padded panel (neither lifts on hover). A section = `Text.Section` header (+ `Note` helper) over its card, 24 between sections, page title `Text.Title` once.
- Switch (`Switch` on a CheckBox, no content): 40 x 24, track Surface3 -> accent fade, 18 px light thumb slides 180 ms, hover veil, focus ring.
- Segment (`Segment` RadioButtons inside a `SegmentHost` Border): 32 high host (Surface2, radius 10, padding 2), 28 high segments (radius 8); the chosen one is a Surface3 tile (fade 120 ms), text Secondary -> Primary. Neutral, not accent.
- Dropdown (`Dropdown` ComboBox): input look (32, Surface2, radius 8, no border), chevron Tertiary, hover veil, 1 px accent while open, focus ring; the list is an overlay (Surface3, hairline, radius 10, elevation 2, items radius 8).
- Slider (implicit `Slider` style): 4 px track Surface3, accent fill, 16 px light thumb with a soft shadow, 24 px hit area, focus ring on the thumb.
- IconButton (`IconButton`): round glyph button, Secondary -> Primary on hover with the white veil, pressed veil, focus ring; colour the glyph with a status brush only for status (a delete in Danger).
- Settings nav (`Nav` in SettingsPage): 36 high pill on `Brush.Section.Panel`, icon 16 px in the category's section hue (`BorderBrush` = `Brush.Section.<Name>`), text Secondary -> Primary on hover, hover veil, selected = the section's tint (`Background` = `Brush.Section.<Name>.Tint`) + the 4 px bar in its hue + Primary text (see "Section colours").
- Input (`Input`, `SecretInput`, the text of `Dropdown`): Surface2 fill, no border at rest, 1 px accent on focus, radius 8, placeholder Secondary. MinHeight 32 (a box without a height is 32 high) and padding 10,4 (multi-line boxes, `AcceptsReturn`, 10,8): 13 px text on an 18 px line needs 18 px of content area, and the old 10,8 left only 14 px of a 32 px box, which cut the descenders of g, j, p, q and y (seen in `invites-gm.png` before 2.40); 10,4 leaves 22. Name / link / address boxes on the invite and lodge forms stay 36 high. Rule for any new input: it must pass the `inputs` self-test (a sample drawn with "lodge gjpqy" at 100 % and 125 %, ink as tall as the same text in a roomy box and never on the box's inner edge) and the audit of the real pages (`ELANSHUB_DESIGN_SHOTS=inputs`, writes `inputs-audit.txt` and a sheet of every input).
- Tooltip: Surface3 + hairline, 12 px, delay 300 ms.
- Toast (`ToastWindow`, in-game, click-through): overlay level (Surface3, `Brush.Edge` hairline, radius 12, `Elevation.2`), padding 16,12, 12 apart, 320-360 wide. 32 px avatar / icon left, title `Text.RowTitle` (class colour only for a member's name) + kind `Text.Caption` Tertiary right, body `Text.Secondary` at most 2 lines (cut at 96 chars). The window has a transparent margin (40 / 32 / 40 / 52) that holds the shadow; `Place` compensates so the card sits 16 px from the screen edge. ## 9. Do / Don't
Do: use tokens; one accent action per view; let size and colour carry hierarchy; keep cards 16 padded and 12 apart; reuse styles.
Don't: add outlines to cards or buttons; use accent for text/numbers/decoration; use more than one semibold per row; invent new sizes (14, 10.5, 11.5, 12.5...) or margins (10, 14, 18); use status colours decoratively; add bouncy or looping motion; hard-code hex colours in pages.

## 10. Checklist for new UI
1. Margins/paddings only from the 4-pt scale; card padding 16, gap 12.
2. Text uses a `Text.*` style; one semibold per row; Secondary text >= 12 px.
3. Colours are `Brush.*` roles; accent only for action/selection; status only for status.
4. Surfaces use fill + elevation, not outlines; radii from the table.
5. Buttons use the 28/32/36 sizes; every focusable control shows the focus ring.
6. Hover and press feedback present (veil, 120 ms); expand/collapse and page changes use `Motion`.
7. Works with Windows animations off, at 125 % DPI, and keyboard only.
8. Add a selftest screenshot and compare before/after (`ELANSHUB_DESIGN_SHOTS`, see `docs/design/`).
9. Run `Tools\design-scan.ps1` (raw hex, off-ramp font sizes, off-grid spacing, odd radii): it must print nothing except the kept-on-purpose looks listed in `docs/design/SWEEP.md`.

## Game tooltips (the one deliberate exception)

Item, spell and Atlas-thing tooltips (`Controls\GameTooltip.cs`) imitate the game's own tooltip on purpose, so they do **not** follow the app theme, accent or radius ramp: a near-black navy panel (`Brush.GameTip.Bg`, ~95 % opaque) with a 1 px grey-blue border (`Brush.GameTip.Border`), radius 4 (`Radius.GameTip`), 13 px lines and a 15 px name, in the game's fixed colours: quality colours `Brush.GameTip.Q0`..`Q7`, white text, Item Level / flavour text / set name gold, effects and bonus stats green, unmet requirements red, missing set pieces grey. All of them are tokens in `Theme.xaml` (so the design scan accepts them); no code may use a raw colour for a game tooltip. The font is the game's Friz Quadrata read from the user's WoW install at run time (`Services\GameFont.cs`, cached in the data folder, never shipped); without it a close system font is used. What the Outpost itself adds (counts, ids, hints) goes into the tooltip's `Footer`: under a hairline, muted, and never mixed into the game's lines. The icon of an item shown on a page sits to the left of the panel in its own 56 px frame.
